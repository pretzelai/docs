The Cord CLI is a first-class wrapper around the [Cord API](/reference/api). You can authenticate, push and pull work between local and cloud, list and create sessions, inspect diffs, open pull requests, manage AI provider connections, and upload files to persistent storage — all without opening the web app.

Under the hood, every `cord` command talks to the same `/api/v1` endpoints you'd use from a script, so anything the CLI does can also be done over HTTP.

## Install

```bash
curl -fsSL https://runcord.com/install.sh | bash
```

This installs the `cord` command (published as the `cord-cli` npm package). Requires Node.js 20.12+.

## Global options

These flags are parsed globally. Command-specific flags only affect the commands that document them.

| Flag | Description |
|---|---|
| `--api-base-url <url>` | Target a different API environment (default: `https://api.runcord.com`). Also settable via `CORD_API_URL` env var. Does not affect `cord self update`. |
| `--json` | Emit raw JSON instead of human-formatted output. Designed for scripts and agents: interactive prompts and update checks are suppressed in JSON mode. |
| `--no-color` | Disable ANSI colors in output. `NO_COLOR` is also honored automatically. |
| `--no-open` | Don't auto-open the browser during login flows (`auth login`, `providers connect`, `push`, `pull`, `status`). |
| `-v`, `--version` | Print the CLI version (as JSON with `--json`). |
| `-h`, `--help` | Print usage info. |

<Tip>
Every command that prints output supports `--json`, including `cord sessions list`, `cord diff`, `cord pr show`, and so on. Use it whenever you're piping Cord into another tool.
</Tip>

## Authentication

The CLI supports two kinds of credentials, both accepted as bearer tokens on the same endpoints:

- **Browser CLI login** (`cord_cli_...`) — minted by `cord auth login` from your browser. Acts as your Cord user. Works for every command including providers.
- **API key** (`cord_sk_...`) — created in **Settings > Cord API**. Scoped to all or selected repositories. Good for CI and automation. Works for sessions, repos, diffs, PRs, and persistent storage. Provider commands require browser CLI auth.

### `cord auth login`

Authenticate the CLI with your Cord account.

```bash
cord auth login [--api-key <key>] [--api-base-url <url>] [--machine-name <name>] [--no-open]
```

| Flag | Default | Description |
|---|---|---|
| `--api-key <key>` | None | Log in with a Cord API key instead of browser device auth. Also settable via `CORD_API_KEY`. API-key auth works for every command except `providers connect/disconnect`, which require browser CLI auth. |
| `--api-base-url` | `https://api.runcord.com` | Target a different Cord API environment |
| `--machine-name` | Your hostname | A name for this device, shown in your account |
| `--no-open` | false | Don't auto-open the browser during device auth |

**How it works:**

1. Cord generates a one-time code and opens a verification URL in your browser
2. You see the code in your terminal:
   ```
   Finish login in your browser
   Code: XXXX-XXXX
   URL:  https://runcord.com/cli/verify?...
   ```
3. Approve the login in your browser
4. The CLI confirms:
   ```
   Logged in
   API:  https://api.runcord.com
   User: Jane Doe
   Org:  org_xxx
   ```

Auth tokens are stored locally at:
- **macOS:** `~/Library/Application Support/cord/config.json`
- **Linux:** `~/.config/cord/config.json`
- **Windows:** `%APPDATA%/cord/config.json`

The config directory is locked to your user (`chmod 700`) and the config file uses `chmod 600`. Auth is stored per API base URL, so prod and staging can stay logged in at the same time.

### `cord auth status`

Check your current login state.

```bash
cord auth status [--api-base-url <url>]
```

Shows your logged-in user, organization, and API base URL. Also lists other environments you're logged into (e.g., staging).

### `cord auth logout`

```bash
cord auth logout [--api-base-url <url>] [--local-only]
```

| Flag | Description |
|---|---|
| `--api-base-url <url>` | Target a different Cord API environment |
| `--local-only` | Clear local config without revoking the remote token |

For browser CLI auth, this revokes the server-side token when possible and clears local config. API-key auth cannot revoke the underlying API key, so logout only clears the local CLI config for that API key.

## Push / Pull

Hand off work between your local machine and Cord cloud sessions. See the full [Push & Pull guide](/guides/push-pull) for workflows and examples.

### `cord push`

Push local work to a Cord cloud session for continuation.

```bash
cord push [--message <msg>] [--context <text>] [--context-file <path>] [--branch <branch>] [--repository <repo>] [--session <id>] [--model <provider/model>] [--thinking <variant>]
```

| Flag | Default | Description |
|---|---|---|
| `--message <msg>` | None | Instruction for what the agent should do next |
| `--context <text>` | None | Inline handoff context |
| `--context-file <path>` | None | Handoff context from a file |
| `--branch <branch>` | Current git branch | Branch for the session |
| `--repository <repo>` | From git remote | GitHub repository (owner/name) |
| `--session <id>` | None | Resume a suspended session |
| `--model <provider/model>` | Your default | Model override |
| `--thinking <variant>` | None | Thinking variant |

Also reads context from stdin when piped.

### `cord pull`

Pull work from a Cord cloud session back to local.

```bash
cord pull [--session <id>] [--branch <branch>] [--repository <repo>] [--output <path>] [--no-suspend]
```

| Flag | Default | Description |
|---|---|---|
| `--session <id>` | None | Explicit session to pull from |
| `--branch <branch>` | Current git branch | Find session by branch |
| `--repository <repo>` | From git remote | Narrow branch lookup |
| `--output <path>` | stdout | Save context to a file |
| `--no-suspend` | false | Keep the cloud session running |

### `cord status`

Check the status of a Cord session linked to the current branch.

```bash
cord status [--session <id>] [--branch <branch>] [--repository <repo>]
```

Prints session status (`running`, `idle`, `blocked`, `error`, `suspended`) and a web UI link. If no session exists for the branch, suggests `cord push`.

## Repositories

### `cord repos list`

Print the full names of every repository the current token can access, one per line.

```bash
cord repos list
```

With `--json`, returns a plain string array — the exact shape of [`GET /api/v1/repositories`](/reference/api#list-repository-names).

### `cord repos details`

Same visibility as `cord repos list`, but renders a table with name, full name, and default branch.

```bash
cord repos details
```

With `--json`, returns the structured `{ repositories: [...] }` payload from [`GET /api/v1/repositories/details`](/reference/api#list-repositories-with-details).

## Sessions

These commands are the terminal equivalent of driving Cord from the web app. Every call goes through the same [public API](/reference/api#sessions) as direct HTTP requests.

### `cord sessions list`

List recent sessions, newest first.

```bash
cord sessions list [--repository <repo>] [--all] [--limit <n>] [--cursor <cursor>]
```

| Flag | Default | Description |
|---|---|---|
| `--repository <repo>` | All visible repos | Filter to one repository (full name, ID, or unambiguous name). |
| `--all` | false | Include archived sessions. |
| `--limit <n>` | `20` | Page size, `1`-`100`. The API default is `50`; the CLI uses `20` so terminal output stays scannable. |
| `--cursor <cursor>` | None | Pagination cursor from a previous run. The CLI prints the next-page command at the bottom when another page is available. |

Human output shows a table with ID, state, repo, relative updated time, and title. Session IDs link through to the web app on terminals that support hyperlinks.

```bash
cord sessions list --repository my-org/my-app --limit 5
```

<Note>
When you're logged in with a browser CLI token, the list is automatically restricted to sessions you created. API-key principals can see every non-private session in their scoped repositories.
</Note>

### `cord sessions show <session-id>`

Show structured details for a session — title, status, branch, timestamps.

```bash
cord sessions show session_xyz789
```

### `cord sessions status <session-id>`

Print the live runtime status — status, lifecycle, activity state, branch.

```bash
cord sessions status session_xyz789
```

Polling-friendly: safe to call repeatedly. Use `--json` if you're driving a state machine from a script.

### `cord sessions create`

Start a new coding session. The agent begins working in the background as soon as the sandbox is ready.

```bash
cord sessions create \
  --repository my-org/my-app \
  --message "Add a /health endpoint that returns status ok" \
  [--model <provider/model>] \
  [--thinking <variant>]
```

| Flag | Required | Description |
|---|---|---|
| `--repository <repo>` | Yes | Repository full name, repo ID, or an unambiguous repository name. |
| `--message <message>` | Yes | The task description for the agent. |
| `--model <provider/model>` | No | Override the model, e.g. `anthropic/claude-sonnet-4`. |
| `--thinking <variant>` | No | Thinking/reasoning variant. `--variant` is accepted as an alias. |

Output includes the new session ID, which you can feed into `cord sessions send`, `cord diff`, `cord pr create`, and friends.

### `cord sessions send <session-id>`

Send a follow-up message into an existing session.

```bash
cord sessions send session_xyz789 \
  --message "Also add tests for the new endpoint." \
  [--model <provider/model>] \
  [--thinking <variant>]
```

Same `--model` / `--thinking` / `--variant` overrides as `cord sessions create`.

## Changes and diffs

### `cord changes <session-id>`

Show the list of files changed in a session — matches `GET /api/v1/sessions/:id/files/changes`.

```bash
cord changes session_xyz789
```

Human output is a color-coded table of status (A/M/D/...), path, and `+additions/-deletions`. `--json` returns the raw payload.

### `cord diff <session-id>`

Show the unified diff for a session. Colored output mirrors `git diff`.

```bash
cord diff session_xyz789
cord diff session_xyz789 --path src/health.ts
```

| Flag | Description |
|---|---|
| `--path <path>` | Restrict the diff to a single file. |

Pair with `--json` to hand the raw diff to another tool:

```bash
cord diff session_xyz789 --json | jq -r .diff | less
```

## Git

### `cord git status <session-id>`

Porcelain-style status of the session's working tree, grouped into Staged / Unstaged / Untracked.

```bash
cord git status session_xyz789
```

Prints the current branch, ahead/behind counts vs. the base branch, and each changed file with a colored status code. Use `--json` for the structured payload.

## Pull requests

### `cord pr show <session-id>`

Show the PR linked to a session, including state and mergeability.

```bash
cord pr show session_xyz789
```

Output:

```
PR #421
State: open
URL:   https://github.com/my-org/my-app/pull/421
Mergeability: clean
```

If no PR is linked yet, the command prints `No pull request linked to this session.`.

### `cord pr create <session-id>`

Create a pull request from the session's current branch.

```bash
cord pr create session_xyz789 \
  [--title "Add /health endpoint"] \
  [--body "Closes #123"] \
  [--draft] \
  [--claim]
```

| Flag | Description |
|---|---|
| `--title <title>` | Override the generated PR title. |
| `--body <body>` | Override the generated PR body. |
| `--draft` | Open as a draft PR. |
| `--claim` | Take over the session as the acting user if it was created by somebody else. |

On success, the CLI prints the resulting PR number, state, and URL.

## Provider connections

### `cord providers list`

Show all connected AI providers and local CLI status.

```bash
cord providers list [--api-base-url <url>]
```

This checks three things in parallel:

1. **Remote connections** -- subscription/provider connections linked to your Cord account (Codex, Claude, Cord Open Source)
2. **Local Codex binary** -- whether `codex` is installed and authenticated on your machine
3. **Local Claude binary** -- whether `claude` is installed and authenticated on your machine

Example output:

```
Cord provider connections
Codex: connected (account-id)
Claude: connected (user@email.com, setup-token)
Cord Open Source: connected (user, key-prefix)

Local provider binaries
Local Codex binary: authenticated, v1.2.3, model_provider=openai
Local Claude binary: authenticated, subscription auth, v2.0.0
```

Provider connect/disconnect commands require browser CLI auth from `cord auth login`; API-key auth is not enough for provider management.

### `cord providers connect codex`

Connect your ChatGPT Plus/Pro subscription to Cord via device code authorization.

```bash
cord providers connect codex [--api-base-url <url>] [--no-open]
```

**Before you start:** You need to enable device code authorization in your ChatGPT account:

1. Open [chatgpt.com/#settings/Security](https://chatgpt.com/#settings/Security)
2. Under "Secure sign in with ChatGPT", toggle ON: **"Enable device code authorization for Codex"**

**Flow:**

1. Run the command and press Enter after enabling device code auth
2. Cord shows a one-time code and opens your browser:
   ```
   Your one-time code:  XXXX-XXXX
   ```
3. Authorize the device in your browser
4. The CLI polls until authorization completes:
   ```
   Codex connected successfully!
   ```

The authorization has a time limit -- complete it before the code expires.

### `cord providers connect claude`

Connect your Claude Max/Pro subscription to Cord.

```bash
cord providers connect claude [--experimental-oauth] [--setup-token] [--token <token>] [--account-uuid <uuid>] [--email-address <email>] [--organization-uuid <uuid>] [--api-base-url <url>] [--no-open]
```

| Flag | Description |
|---|---|
| `--experimental-oauth` | Explicitly request Claude browser OAuth. This is already the default and cannot be combined with `--setup-token`, `--token`, or `CLAUDE_CODE_OAUTH_TOKEN`. |
| `--setup-token` | Use the setup-token flow instead of browser OAuth |
| `--token <token>` | Directly provide a Claude setup-token (skips interactive flow) |
| `--account-uuid <uuid>` | Override Claude account metadata sent to Cord |
| `--email-address <email>` | Override Claude email metadata sent to Cord |
| `--organization-uuid <uuid>` | Override Claude organization metadata sent to Cord |
| `--api-base-url <url>` | Target a different Cord API environment |
| `--no-open` | Don't auto-open the browser during OAuth |

<Tabs>
  <Tab title="Browser OAuth (default)">
    The default flow opens your browser to authorize with Claude:

    ```bash
    cord providers connect claude
    ```

    Cord opens Claude's OAuth consent page. Approve the connection, and the CLI stores your credentials securely:

    ```
Connected Claude
Stored your Claude OAuth credential set in Cord.
```

    This method automatically handles token refresh -- you won't need to reconnect unless you revoke access.
  </Tab>
  <Tab title="Setup token">
    If you prefer not to use browser OAuth, use the setup-token flow:

    ```bash
    cord providers connect claude --setup-token
    ```

    If Claude Code is installed, authenticated with a Claude subscription, running in an interactive terminal, and on macOS or Linux, the CLI offers to auto-generate the token:

    ```
    Use your local Claude login to generate a remote setup-token for Cord now? [Y/n]
    ```

    Press **Y** and the CLI runs `claude setup-token` automatically. If Claude Code isn't available, is using API-key auth, or can't be verified as a subscription login, you'll be prompted to paste a token manually.

    You can also provide a token directly:

    ```bash
    cord providers connect claude --token sk-ant-oat...
    ```

    Or set the `CLAUDE_CODE_OAUTH_TOKEN` environment variable. The CLI only uses this environment variable with `--setup-token`; without `--setup-token`, browser OAuth remains the default.

    ```bash
    export CLAUDE_CODE_OAUTH_TOKEN=sk-ant-oat...
    cord providers connect claude --setup-token
    ```
  </Tab>
</Tabs>

<Tip>
The CLI reads Claude metadata from `~/.claude.json` and `~/Library/Application Support/Claude/.claude.json` when present. For setup-token flows, it can also use the email detected from local `claude auth status`. You can override metadata with `--account-uuid`, `--email-address`, or `--organization-uuid` flags if needed.
</Tip>

### `cord providers disconnect codex`

```bash
cord providers disconnect codex [--api-base-url <url>]
```

Removes your Codex subscription connection from Cord.

### `cord providers disconnect claude`

```bash
cord providers disconnect claude [--api-base-url <url>]
```

Removes your Claude subscription connection from Cord.

## Storage upload

Upload files and folders to your [persistent storage](/core-concepts/persistent-storage) from the command line.

### `cord storage upload`

```bash
cord storage upload <path> [--name <name>] [--mount-path <path>] [--repo-id <id>] [--no-mount] [--include-sensitive] [--api-base-url <url>]
```

| Flag | Default | Description |
|---|---|---|
| `--name <name>` | Basename of the path | Display name for the attachment |
| `--mount-path <path>` | None (stored only) | Where to mount in sandboxes (e.g., `~/.bashrc`, `/repo/.config`) |
| `--repo-id <id>` | None (all repos) | Restrict mount to a specific repository |
| `--no-mount` | false | Store without mounting (configure mount later in Settings) |
| `--include-sensitive` | false | Include files that look like secrets |
| `--api-base-url <url>` | `https://api.runcord.com` | Target a different Cord API environment |

`--repo-id` requires `--mount-path`. `--no-mount` cannot be combined with `--mount-path` or `--repo-id`.

### Uploading a single file

```bash
# Upload your bashrc to every sandbox
cord storage upload ~/.bashrc --mount-path "~/.bashrc"

# Upload an env file for a specific repo
cord storage upload .env.local --mount-path "/repo/.env.local" --repo-id repo_abc123 --include-sensitive

# Upload without mounting (configure later in the web UI)
cord storage upload ./my-config.json --no-mount
```

### Uploading a folder

```bash
# Upload a config directory
cord storage upload ./my-config --mount-path "/repo/.config" --name "project config"

# Upload Claude skills
cord storage upload ~/.claude/skills --mount-path "~/.claude/skills"
```

When uploading a folder, Cord recursively walks the directory and uploads all files. Progress is shown in real-time:

```
Uploading files: 45.2% (12.3 MB/27.1 MB, 42/100 files)
```

Progress phases include `Preparing upload`, `Uploading files`, and `Finalizing upload`.

### What gets skipped

By default, directory uploads skip files and directories that look like secrets or aren't useful in a sandbox. Single-file uploads that look sensitive are rejected unless you pass `--include-sensitive`. Hidden files and folders are included unless they match sensitive rules.

**Skipped directories:** `.aws`, `.git`, `.gnupg`, `.ssh`

**Skipped files:** `.env`, `.env.*`, `*.key`, `*.pem`, `*.p12`, `*.pfx`, `id_rsa`, `id_dsa`, `id_ecdsa`, `id_ed25519`, `credentials`, `credentials.json`, `.credentials.json`, `.npmrc`, `.netrc`, and similar credential files.

**Also skipped:** Symlinks (not followed), empty directories (not preserved), non-regular files (sockets, block devices).

Use `--include-sensitive` to override secret detection and upload everything:

```bash
cord storage upload ./my-config --mount-path "/repo/.config" --include-sensitive
```

### Upload limits

| Limit | Value |
|---|---|
| Max files per upload | 5,000 |
| Max single file size | 200 MiB |
| Max total upload size | 1 GiB |

<Info>
If you upload without a mount path, the file is stored but not auto-mounted. You can configure the mount path later in **Settings > Persistent Storage**.
</Info>

### `cord storage sync-skills`

Upload global Claude skills and global agent skills into persistent storage.

```bash
cord storage sync-skills [--yes] [--include-sensitive] [--api-base-url <url>]
```

This scans the standard local skill directories and mounts them into future sandboxes:

| Local path | Sandbox mount path |
|---|---|
| `~/.claude/skills` | `~/.claude/skills` |
| `~/.agents/skills` | `~/.agents/skills` |

The command skips missing directories and directories with no uploadable regular files. In an interactive terminal, it asks before uploading. It replaces existing directory attachments at the same target paths, mounts them for all repositories, and changes apply to new sandboxes only.
