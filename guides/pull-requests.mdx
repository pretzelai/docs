## Creating a PR

When the agent finishes (or at any point during a session), click **Create PR**. A popover lets you:

- **Edit the title** -- Cord generates one automatically, you can change it
- **Edit the description** -- AI-generated summary of changes, editable before submission
- **Toggle draft** -- create as a draft PR if it's not ready for review yet

Cord pushes the branch to GitHub and opens the pull request. The PR links back to the session.

<Tip>
You can create the PR straight from your terminal without opening Cord:

```bash
cord pr create <session-id> --title "Add /health endpoint" --draft
cord pr show <session-id>   # check state, URL, and mergeability
```

This is handy for CI pipelines that drive Cord end-to-end — kick off a session with `cord sessions create`, watch it with `cord sessions status`, review with `cord diff`, and open the PR with `cord pr create`. Everything is wired through the [Cord API](/reference/api#pull-requests) too if you'd rather make HTTP calls directly.
</Tip>

## AI-generated PR descriptions

When you click Create PR, Cord generates a title and description based on:

- The conversation in the session
- The actual code changes made
- The original task description

You can edit both before submitting. The description is formatted with a summary, list of changes, and a link to the Cord session.

## Quick PR

For straightforward changes, use **Quick PR** -- a one-click shortcut that creates a PR with auto-generated title and description, skipping the popover. Enable it in **Settings > GitHub > PR Shortcuts**.

## YOLO mode

**YOLO** goes one step further: it creates a PR, merges it immediately, and archives the session -- all in one click. Useful for trivial changes where you trust the agent's output and don't need a review cycle.

Enable YOLO in **Settings > GitHub > PR Shortcuts**.

<Warning>
YOLO bypasses your normal review process. It will still respect GitHub branch protection rules and required status checks -- if CI fails, the merge won't go through.
</Warning>

## Reviewing diffs

The **Changes** panel shows all modified files with a GitHub-style diff view:

- Lines added (green) and removed (red)
- Full file context around changes
- Per-file diff counts in the sidebar
- Expand/collapse individual files

## Live preview

If your project runs a dev server, check the live preview URL before merging. The preview runs in the sandbox and shows exactly what the code changes look like. Share the URL with teammates for a quick visual review.

## Updating a PR

If you give the agent follow-up instructions after creating a PR, the new commits are pushed to the same branch. The PR updates automatically -- no need to create a new one.

## Merge conflicts

If the base branch has changed since the session started:

- Cord flags the conflict in the session status
- Ask the agent to resolve it: *"Rebase on main and resolve the merge conflicts"*
- Or resolve manually through GitHub's conflict resolution UI

## Merging

Merge from Cord or from GitHub -- either works. After merge:

- The session status updates to **Merged**
- The sandbox can be suspended

## Keep working after merge

Click **Keep Working** to start a new session that:

- Branches from the latest main (including your merged changes)
- Has context of what was done in the previous session
- Lets the agent continue building on top of the merged work

Useful for multi-step features where you want to merge incrementally rather than pile everything into one giant PR.

## Adopting an existing PR

If you have a PR on GitHub that was created outside of Cord (manually, by another tool, etc.), you can **adopt** it into a Cord session:

1. In the chat input, reference the PR
2. Cord checks out the PR's branch into a sandbox
3. The agent has full context of the existing changes
4. You can give the agent instructions to continue, fix, or improve the PR

This is useful for picking up half-finished work or having the agent fix CI failures on an existing PR.

## PR flow progress

When creating a PR, Cord shows a real-time progress card:

1. **Staging** -- collecting changes
2. **Committing** -- creating the git commit
3. **Pushing** -- pushing the branch to GitHub
4. **Creating PR** -- opening the pull request

If any step fails, you'll see the error and can retry.
