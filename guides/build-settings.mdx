Build settings are in **Repository Settings** (gear icon on any repo). Six tabs:

| Tab | What it controls |
|---|---|
| **Build Config** | Install/build commands, runtime processes, endpoints, sandbox provider |
| **Environment** | Secret files (env vars), mounted persistent storage |
| **Builds** | Prebuilt image management, build logs, rebuilds |
| **Agent & Model** | Default agent and model for this repo |
| **AI Tools** | Repo-scoped MCP servers and skills |
| **Testing** | Browser testing instructions for the agent |

---

## Build Config

### Root directory

For monorepos, set the subdirectory (e.g., `apps/web`). All commands run from here.

### Install command

Auto-detected from your lockfile:

| Lockfile | Default command |
|---|---|
| `pnpm-lock.yaml` | `pnpm install` |
| `yarn.lock` | `yarn install` |
| `package-lock.json` | `npm install` |
| `bun.lockb` | `bun install` |

Override with custom flags if needed (e.g., `pnpm install --frozen-lockfile`).

### Build command

Optional. Runs after install for TypeScript compilation, codegen, etc.

### Build hooks

Additional commands after build, one per line. For native deps, migrations, seed scripts, system packages. Run in order during image build.

### Sandbox provider

Choose which provider runs your sandboxes. Availability is deployment-specific. If using Docker Compose, choose a provider that supports it.

## Runtime processes

Define what runs in your sandbox. Click **Add Process**:

| Field | Description |
|---|---|
| **Name** | Human-readable label (e.g., "Frontend", "API Server") |
| **Runner** | How the process is executed -- **Command** or **Docker Compose** |
| **Command** | The shell command to run (e.g., `npm run dev`, `python manage.py runserver`) |
| **Working directory** | Subdirectory to run from, relative to the repo root. Leave blank for repo root. |
| **Auto-start** | Whether the process launches automatically in new sessions (default: yes) |

Up to **16 processes** per repository.

### Docker Compose runner

Select **Docker Compose** as the runner for Compose projects:

| Field | Description |
|---|---|
| **Compose files** | Paths to your compose files (default: `docker-compose.yml`). One per line. |
| **Project name** | Optional stable project name for the compose stack. |

<Info>
Docker Compose requires a provider that supports it.
</Info>

## Endpoints

Each process can expose ports as tunnel URLs. Click **Add Endpoint**:

| Field | Description |
|---|---|
| **Name** | Label for this endpoint (e.g., "Web UI", "API") |
| **Port** | The port number your service listens on (1--65535) |
| **Exposure** | How the endpoint is accessed (see below) |

### Exposure levels

| Level | Description |
|---|---|
| **Primary** | Default preview URL. One per process. |
| **Exposed** | Browser-accessible but not default. |
| **Internal** | Sandbox-only, no external URL. |

Up to 16 endpoints per process, 11 exposed total.

### Reserved ports

`4096`, `4097`, `4098`, `4190`, `7681`, `18080`

### Docker Compose endpoints

For Compose processes, also requires:

| Field | Description |
|---|---|
| **Service name** | Which Compose service this port belongs to |
| **Container port** | The port inside the container (may differ from the host port) |

## Environment

Each entry:

| Field | Description |
|---|---|
| **File path** | Where the file is written in the sandbox (e.g., `.env`, `apps/web/.env.local`) |
| **Content** | The file contents (typically `KEY=VALUE` pairs) |

Encrypted at rest, injected at startup, write-only in the UI.

### Mounted files

Files from [persistent storage](/core-concepts/persistent-storage) configured for this repo. Manage in **Settings > Persistent Storage**.

## Builds (prebuilt images)

Docker image with dependencies pre-installed for faster sandbox startup. Runs install, build, and hooks, then snapshots.

### Build phases

1. Create sandbox → 2. Clone repo → 3. Install → 4. Build → 5. Hooks → 6. Snapshot → 7. Cleanup

### Managing builds

In the Builds tab: view history, view logs, trigger rebuild, cancel in-progress builds.

### When to rebuild

After dependency changes, command changes, or when sessions fail to start with missing deps.

## Agent & Model

Override org defaults for this repo. Users can still override per-session with **Cmd+/**.

### Cross-repository access

When enabled, the sandbox gets a GitHub token that can clone any repo in your GitHub App installation. For projects depending on private packages from other repos.

<Warning>
The AI agent will be able to read code from other repos in your org.
</Warning>

---

## AI Tools

Repo-scoped MCP servers and skills, in addition to org and user-level ones.

**Effective config preview** shows the merged configuration new sessions receive.

---

## Testing

Free-text instructions telling the agent how to test in the browser. Two scopes: **For everyone** (admin, repo-wide) and **For me** (personal override). Read during headless browser verification.

---

## Auto-detection

**Set up automatically** inspects your repo (file structure, package.json, Dockerfiles) and proposes a full config. Accept, iterate via chat, or switch to manual.
