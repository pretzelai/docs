## Starting a session

Pick a repo and type what you want. That's it — the agent starts immediately.

The model defaults to your configured preference. Switch it anytime with **Cmd+/** to open the model selector, or change it mid-session.

<Tip>
You can also start sessions from your terminal:

```bash
cord sessions create --repository my-org/my-app \
  --message "Add a /health endpoint that returns status ok"
```

Or hand off from a local agent with [Push & Pull](/guides/push-pull) — say "push to Cord" and your local agent sends its work to the cloud.
</Tip>

## Writing good prompts

Be specific. Reference files. Describe what "done" looks like.

```
Add a GET /api/health endpoint to the Express server in src/server.ts
that returns { status: "ok", timestamp: Date.now() }
```

```
Create a user registration form with email and password fields.
Validate email format and min 8-char password.
Show inline errors. Add tests.
```

Type `@` to mention files, sessions, PRs, skills, or MCP tools — they're attached as context for the agent.

## Attaching context

Paste, drag-and-drop, or use the file picker to attach screenshots, mockups, error logs, or documents. The agent sees them alongside your prompt.

## The workspace

While the agent works, the session layout gives you:

- **Chat** — the agent's reasoning, tool calls (collapsed by default), and questions
- **Changes** — files modified, with a diff view in the right sidebar
- **Terminal** — command output from builds, tests, and servers (drag handle to resize)
- **Preview** — your dev server running at a unique URL

## Slash commands

Type `/` in the chat input:

| Command | What it does |
|---|---|
| `/model` | Switch model or thinking level |
| `/voice` | Dictate a message |
| `/expand` | Show native terminal panels for active sandboxes |
| `/repository` | Switch active repository for new sessions |

Skills and MCP servers can register additional slash commands.

## Quick actions

Below the chat input, action buttons give you one-click access to common operations:

- **Undo** / **Redo** — rewind or restore the agent's last step
- **Compact** — summarize the conversation to reclaim context space
- **Review** — ask the agent to self-review its changes before you look at the diff

## Build mode vs Plan mode

Toggle with **Shift+Tab**:

- **Build mode** (default) — the agent reads, writes, and runs code
- **Plan mode** — the agent analyzes and plans without making file changes. Use it to discuss architecture or get a plan before committing.

## Scratch pad

Press **Alt+S** to open the scratch pad. Draft requirements, keep notes, or write context you can reference later with `@notes`.

## Context capacity

The context capacity ring in the chat input shows how full the agent's context window is. Colors shift from blue → amber → red as it fills. When it's getting full, use **Compact** to summarize and reclaim space, or start a fresh session.

## Stopping the agent

Press **Escape** once to see a warning, **Escape** again to confirm. Code changes made so far are preserved.

## Iterating

Keep going after the agent finishes — ask for changes, report issues, add requirements. You can queue a follow-up message while the agent is still working; it's delivered when the current step completes.

## Voice input

Tap the microphone icon (or use `/voice`) to dictate instead of typing. Works on desktop and mobile. The transcribed text appears in the composer for review before sending.

In **Settings > UI Preferences**, toggle **Autosend after voice dictation** to skip the review step.

## Notifications

When sessions run in the background:

- The favicon updates to show a running indicator
- You get a browser notification (or push notification on mobile) when a session finishes
- Notifications link directly to the finished session
