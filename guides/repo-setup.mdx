## Connecting a repository

1. Go to your Cord dashboard
2. Click **Add Repository**
3. Select a repo from your GitHub installations
4. Choose **Set up automatically** or configure manually

You can connect repos from any GitHub org where the Cord GitHub App is installed.

## Automatic setup

When you choose automatic setup, Cord's AI inspects your repo — reading `package.json`, Dockerfiles, config files — and proposes a complete build configuration. You can accept it as-is, chat with the AI to refine it, or switch to manual setup at any time.

It handles standard setups well (Next.js, Vite, Express, Django, Rails). Unusual configurations may need manual tweaking.

## Build configuration

In **Repository Settings > Build Config**:

### Root directory

For monorepos or subdirectory projects, set the root (e.g., `apps/web`). All commands run from this path.

### Install command

Cord auto-detects this from your lockfile:

| Lockfile | Default |
|---|---|
| `pnpm-lock.yaml` | `pnpm install` |
| `yarn.lock` | `yarn install` |
| `package-lock.json` | `npm install` |
| `bun.lockb` | `bun install` |

### Build command

Optional. Runs after install — for TypeScript compilation, codegen, or any build step needed before dev server start.

### Build hooks

Additional commands that run after the build command, one per line. Use these for database migrations, seed scripts, installing native dependencies, or anything else your project needs during image setup.

## Runtime processes

Define what runs inside your sandbox. Most projects need at least a dev server. Complex projects might have a frontend, backend, database, and worker.

Each process has a name, a command (e.g., `npm run dev`), and optionally a working directory. You can also use **Docker Compose** as the runner if your project has a `docker-compose.yml`.

Processes start automatically when a session begins (configurable per-process).

## Endpoints

Each process can expose ports as preview URLs. Mark one as **Primary** (the default preview that opens when you click Preview in a session), others as **Exposed** (accessible but not default), or **Internal** (sandbox-only, no external URL).

## Secret files

Add sensitive configuration in **Repository Settings > Environment**. Each entry is a file path + content (e.g., `.env` with your `KEY=VALUE` pairs). Files are:

- Encrypted at rest
- Written to the sandbox at the specified path on startup
- Write-only in the UI — you can update but not read back values

<Warning>
Secret files are accessible to the AI agent in your sandbox. Don't add credentials you wouldn't want a model to see.
</Warning>

## Per-repo defaults

Override org-level settings for a specific repository:

| Setting | Description |
|---|---|
| **Default agent** | Claude Code or OpenCode |
| **Default model** | Provider, model, and thinking variant |

Individual users can still override per-session via the model selector.

## Builds

Cord builds a Docker image with your dependencies pre-installed so sandboxes start fast. View build history, logs, and trigger rebuilds in the **Builds** tab.

<Tip>
If a new session fails to start or has missing dependencies, trigger a rebuild. This refreshes the base image with the latest dependency state.
</Tip>

For the full reference on every build setting — Docker Compose configuration, endpoint exposure levels, reserved ports, and more — see [Build settings](/guides/build-settings).
