## Connecting a repository

1. Go to your Cord dashboard
2. Click **Add Repository**
3. Select a repo from your GitHub installations
4. Choose **Set up automatically** or configure manually

## Automatic setup

Cord's AI reads your `package.json`, Dockerfiles, and config files to propose a build configuration. You can accept, refine via chat, or switch to manual.

Works well for standard setups (Next.js, Vite, Express, Django, Rails).

## Build configuration

In **Repository Settings > Build Config**:

### Root directory

For monorepos, set the subdirectory (e.g., `apps/web`). All commands run from this path.

### Install command

Auto-detected from your lockfile:

| Lockfile | Default |
|---|---|
| `pnpm-lock.yaml` | `pnpm install` |
| `yarn.lock` | `yarn install` |
| `package-lock.json` | `npm install` |
| `bun.lockb` | `bun install` |

### Build command

Optional. Runs after install for TypeScript compilation, codegen, etc.

### Build hooks

Additional commands after build, one per line. For migrations, seed scripts, native deps, etc.

## Runtime processes

Define what runs inside your sandbox. Each process has a name, a command (e.g., `npm run dev`), and optionally a working directory. Docker Compose is also supported as a runner.

Processes auto-start when a session begins (configurable per-process).

## Endpoints

Each process can expose ports as preview URLs:

- **Primary** — default preview when you click Preview
- **Exposed** — accessible via URL but not the default
- **Internal** — sandbox-only, no external URL

## Secret files

In **Repository Settings > Environment**, add file path + content pairs (e.g., `.env`). Files are encrypted at rest, injected at sandbox startup, and write-only in the UI.

<Warning>
Secret files are accessible to the AI agent. Don't add credentials you wouldn't want a model to see.
</Warning>

## Per-repo defaults

| Setting | Description |
|---|---|
| **Default agent** | Claude Code or OpenCode |
| **Default model** | Provider, model, and thinking variant |

## Builds

Cord builds a Docker image with dependencies pre-installed so sandboxes start faster. View history, logs, and trigger rebuilds in the **Builds** tab.

If a session fails to start with missing dependencies, trigger a rebuild.

For the full reference see [Build settings](/guides/build-settings).
