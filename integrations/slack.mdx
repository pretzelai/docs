<Info>
Slack integration is available on all plans, including **Free**.
</Info>

Connect Cord to your Slack workspace so anyone on your team can start an agent without leaving Slack.

## Setup

1. Go to **Settings > Slack**
2. Click **Connect Slack**
3. Authorize the Cord app in your Slack workspace

Once connected, Cord appears as a bot (`@Cord`) in your workspace.

## Team mapping

After connecting, Cord auto-maps team members by matching GitHub and Slack email addresses. You can check mapping status in the Slack settings tab -- it shows which team members are linked and which aren't.

If mappings get out of sync (new team members, changed emails), click **Re-sync Members** to refresh.

### Personal Slack linking

Each team member can also link their personal Slack account in settings. This ensures their Slack messages are attributed to the correct Cord user.

## Usage

Tag `@Cord` in any channel with a task description:

```
@Cord Add rate limiting to the /api/auth endpoints.
Use express-rate-limit, 100 requests per 15 minutes per IP.
```

Cord will:

1. Identify which repo to work on
2. Spin up a sandbox
3. Start an agent on the task
4. Post updates in a thread as the agent works
5. Share the PR link when done

## Repo routing

Cord uses AI to determine which repository a Slack message should be routed to, based on:

- Channel context and history
- Previous routing patterns
- The content of your message

You can always be explicit:

```
@Cord In the frontend repo, fix the broken dropdown on the settings page.
```

## Images in Slack

You can paste or upload images in your Slack message to Cord. The agent receives them as context -- useful for:

- Bug reports with screenshots
- Design mockups to implement
- Error screenshots from the browser

<Tip>
If image attachments aren't working, check that the Cord Slack app has the `files:read` scope. You'll see a warning in **Settings > Slack** if the scope is missing.
</Tip>

## Slack memory

Cord can maintain **per-user durable memory** across Slack-started sessions. When enabled, Cord remembers context from your previous interactions -- your preferences, common patterns, and recurring instructions.

### Enabling Slack memory

Admins toggle Slack memory in **Settings > Slack > Enable Slack Memory**. Once enabled:

- Each user gets a personal memory context
- The memory is included in Slack-triggered sessions
- Users can view and edit their memory in **Settings > Slack > Personal Slack Memory**

### Editing your memory

Your Slack memory is a free-text field where Cord stores context it's learned about your preferences. You can edit it directly to:

- Add recurring instructions ("always use TypeScript strict mode")
- Remove incorrect assumptions
- Add project-specific context

## Slack system prompt

Admins can configure a **custom system prompt** for Slack-triggered sessions in **Settings > Slack > Slack System Prompt**. This prompt is injected into every session started from Slack.

Use it for:

- Team-wide coding standards
- Project conventions
- Repo-specific instructions that should apply to every Slack-started task

Leave it empty to use Cord's default prompt.

## Auto-provisioning

When enabled by an admin (**Settings > Slack > Auto-provision**), Cord automatically creates accounts for Slack users who tag `@Cord` for the first time. This removes the need to manually invite everyone -- they just start using it.

## Thread replies as instructions

Reply in a Slack thread where Cord is working to give the agent follow-up instructions. Tag `@Cord` in your reply so it gets picked up:

```
@Cord Add rate limiting to /api/auth

  → (Cord starts working in a thread)

You: @Cord Actually use a sliding window instead of fixed window
You: @Cord And add tests

  → (Agent picks up both replies as new instructions)
```

Replies from other team members in the thread work the same way — tag `@Cord` and the agent receives it as context. This is useful for collaborative steering without leaving Slack.

## File sharing

Agents can share files from the sandbox back to the Slack thread — logs, screenshots, build output, or any artifact. When the agent generates a file worth sharing (like a test report or error log), it posts it as an attachment in the thread.

This also works in reverse: files you upload in your Slack message are passed to the agent as context.

## Notifications

When an agent finishes, Cord posts in the original Slack thread with:

- A summary of what was done
- A link to the PR
- A link to the session in Cord
