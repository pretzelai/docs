When you sign up for Cord, an onboarding wizard walks you through everything. Here's what to expect.

## 1. Create your account

Go to [runcord.com](https://runcord.com) and sign up with **GitHub**, **Google**, or **email/password**.

Cord creates a workspace for you automatically. You can rename it and invite teammates later in [Org setup](/guides/org-setup).

## 2. Connect a model provider

The onboarding wizard starts here. You need an AI provider before you can start a session. Pick one:

<Tabs>
  <Tab title="Starter credit (recommended)">
    Claim your **$100 starter credit** -- $50 for Claude and $50 for OpenAI. One click, no credit card needed, credits don't expire. This is the fastest way to try both agents.
  </Tab>
  <Tab title="Free open source models">
    Select **Cord Open Source** as your provider. This gives you access to models like **Kimi K2.6**, **Qwen 3.6 Plus**, **GLM 5.1**, and **MiniMax M2.7** at no cost. No API key needed.
  </Tab>
  <Tab title="API key">
    Select a provider (Anthropic, OpenAI, Google, etc.) and paste your API key. The key is verified before saving. Expand **Advanced options** to set a custom base URL if needed.
  </Tab>
  <Tab title="Claude subscription">
    If you have a Claude Max/Pro subscription, paste a setup token. Generate one by running `claude setup-token` in your terminal.
  </Tab>
  <Tab title="ChatGPT / Codex subscription">
    Click **Start device authorization** to get a one-time code. Open the ChatGPT link, enter the code, and Cord polls until the connection completes.
  </Tab>
</Tabs>

<Tip>
**For team admins:** You can set org-level shared API keys in **Settings > Organization** so your whole team uses the same provider without each person configuring their own. See [Org setup](/guides/org-setup).
</Tip>

## 3. Connect GitHub

Click **Connect GitHub**. You'll be redirected to GitHub to install the Cord GitHub App. Choose your organization or personal account and select which repositories to grant access to.

After authorizing, you're redirected back to Cord automatically.

## 4. Pick a repository

Search for and select a repository to connect. Cord shows all repos available through your GitHub App installation -- you can filter by name, see the language, and whether it's private.

## 5. Configure your repo

After connecting a repo, Cord walks you through three setup steps:

<Steps>
  <Step title="Build config">
    Choose **Set up automatically** to have Cord's AI inspect your repo and propose a build configuration (package manager, build commands, dev server, port). You can accept the proposal or iterate on it in a chat. Or choose **Set up manually** to fill in the fields yourself.
  </Step>
  <Step title="Environment variables">
    Add any environment variables or secret files your project needs. These are encrypted and injected into every sandbox. You can skip this step if your project doesn't need env vars.
  </Step>
  <Step title="Prebuilt image (optional)">
    Cord can build a Docker image with your dependencies pre-installed so sandboxes start faster. This step is optional -- you can skip it and sandboxes will install dependencies on each start.
  </Step>
</Steps>

Each step has a **Skip** button if you want to configure it later.

## 6. Start your first session

You're now on the dashboard. Click **New Session** on your repository, pick your agent, and type your request:

```
Add a GET /api/health endpoint that returns { "status": "ok", "timestamp": Date.now() }.
Include a test for the new endpoint.
```

Watch the agent work in real-time:
- **Chat** -- the agent's reasoning and progress
- **Changes** -- files being modified with live diff counts
- **Terminal** -- command output from builds and tests
- **Preview** -- your dev server running at a unique URL

## 7. Review and create a PR

Once the agent finishes:

1. **Review the diff** in the Changes panel
2. **Check the live preview** -- click the preview URL to see your running app with the changes
3. **Create a PR** -- click the button, and a pull request opens on GitHub

Your existing CI/CD, branch protection rules, and code review workflows all work as normal -- it's a standard GitHub PR.
