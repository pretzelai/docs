title: "Persistent storage"
description: "Files, config, and tools that carry over across sandbox sessions."
---

Every user gets persistent storage that survives across sandbox sessions. Anything that doesn't belong in the repo but should be available every time you start a new session goes here.

## What persists

- **`.claude/` directory** -- Your Claude Code configuration, skills, and memory files
- **`.agents/` directory** -- Agent skills and configuration for OpenCode
- **Dotfiles** -- `.bashrc`, `.gitconfig`, editor settings
- **Test artifacts** -- Cached builds, test snapshots
- **Custom tools** -- CLI tools or scripts you've installed
- **Secret files** -- Env files or configs you don't want in your repo

## How it works

Persistent storage is backed by cloud storage and mounted into every sandbox when it starts. Think of it as your home directory that follows you from session to session.

Storage is **per-user**, not per-repo. Your personal configuration is available regardless of which repository you're working in.

## Uploading files

You can upload files and folders through the Cord UI:

1. Go to **Settings > Persistent Storage**
2. Click **Upload** or drag-and-drop files
3. Configure the mount path (where the file appears in the sandbox, e.g. `~/.bashrc` or `/repo/.claude`)
4. Choose the scope -- **all repositories** or a **specific repo**
5. Toggle **auto-mount** to include it in new sandboxes by default

### Mount paths

Each uploaded file or folder gets a mount path that determines where it appears in the sandbox filesystem. For example:

| File | Mount path | Result |
|---|---|---|
| `.bashrc` | `~/.bashrc` | Replaces the default `.bashrc` in your sandbox home directory |
| `claude/` | `/repo/.claude` | Mounts your Claude config into the repo root |
| `.env.local` | `/repo/.env.local` | Injects an env file into the project |

### Repo scoping

By default, files mount into all repositories. You can scope a file to a specific repo if it only applies there (e.g., an `.env.local` with repo-specific secrets).

### Managing files

In the persistent storage settings, you can:

- **Edit settings** -- rename, change mount path, toggle auto-attach
- **Replace contents** -- re-upload a new version of a file
- **Resume uploads** -- retry if an upload was interrupted
- **Delete** -- remove files you no longer need

## Syncing local skills

If you have Claude Code or OpenCode skills configured on your local machine, sync them with the CLI:

```bash
curl -fsSL https://runcord.com/install.sh | bash
```

This uploads your local `~/.claude/skills` and `~/.agents/skills` directories. Run it again any time you update your local skills.

## CLI upload

You can also upload files from the command line:

```bash
# Upload a file
cord storage upload ~/.bashrc --mount-path "~/.bashrc"

# Upload a folder
cord storage upload ./my-config --mount-path "/repo/.config" --name "project config"

# Upload to a specific repo only
cord storage upload .env.local --mount-path "/repo/.env.local" --repo-id repo_abc123
```

Options:

| Flag | Description |
|---|---|
| `--name` | Display name for the attachment |
| `--mount-path` | Where to mount in the sandbox |
| `--repo-id` | Scope to a specific repository |
| `--no-mount` | Upload without mounting |
| `--include-sensitive` | Include files normally excluded (e.g. `.env`) |

<Tip>
Persistent storage is automatically available in every new sandbox. You don't need to configure anything per-session -- just start a session and your files are there.
</Tip>
